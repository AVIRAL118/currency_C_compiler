# Currency-C Compiler

A Python-based compiler front-end for **Currency-C**, a custom C-like programming language that introduces currency-aware data types and semantic checking.

The project implements a four-phase compilation pipeline: lexical analysis, syntax analysis, semantic analysis, and C code generation. It translates valid Currency-C programs (`.cur`) into C source code.

## Overview

Currency-C extends familiar C-style programming constructs with a dedicated `currency` type. Currency values carry an associated currency code, allowing the semantic analyzer to check whether arithmetic and assignments are type-compatible.

For example:

```c
currency<INR> salary = ₹50000;
currency<INR> bonus = ₹2500;
currency<INR> total;

total = salary + bonus;
output(total);
```

The compiler processes the source program, constructs an Abstract Syntax Tree (AST), performs semantic checks, and generates equivalent C code.

## Compilation Pipeline

The compiler consists of four phases:

### Phase 1 — Lexical Analysis

**File:** `lexer.py`

- Implements a hand-written lexer using Python's `re` module.
- Converts source code into categorized tokens.
- Recognizes keywords, identifiers, currency codes, currency symbols, literals, operators, and delimiters.
- Tracks line and column information for lexical errors.
- Handles single-line and multi-line comments.

### Phase 2 — Syntax Analysis

**File:** `parser.py`

- Implements a hand-written recursive descent parser.
- Uses the token stream generated by the lexer.
- Validates source code against the implemented grammar.
- Constructs an Abstract Syntax Tree (AST).
- Supports declarations, assignments, expressions, blocks, conditionals, loops, and other supported statements.
- Reports syntax errors with line numbers.

### Phase 3 — Semantic Analysis

**Files:** `semantic.py`, `symbol_table.py`

- Maintains symbol and structure information.
- Implements scoped symbol lookup and type checking.
- Checks variable declarations, assignments, expressions, pointers, and structure member access.
- Enforces currency compatibility rules.
- Reports semantic errors and warnings, including incompatible currency operations and invalid assignments.

### Phase 4 — C Code Generation

**File:** `codegen.py`

- Traverses the validated AST using a visitor-based approach.
- Translates Currency-C declarations and expressions into C.
- Maps currency types to C `float` representations.
- Generates appropriate `printf()` and `scanf()` formats based on expression types.
- Preserves supported structures, pointers, arrays, control flow, and file-function calls.
- Writes the generated C source to `output.c`.

## Supported Language Features

| Category | Supported constructs |
|---|---|
| Data types | `int`, `float`, `FILE`, `struct`, `currency<CODE>` |
| Currency codes | INR, USD, EUR, GBP |
| Currency literals | ₹, $, €, £ |
| Declarations | Variables, pointers, arrays |
| Structures | Struct definitions and member access |
| Expressions | Arithmetic, relational, equality, logical, unary |
| Control flow | `if`, `else`, `while`, `return` |
| Input/output | `input()` and `output()` |
| File operations | Selected file-function calls |

## Currency-Aware Type Rules

The semantic analyzer applies currency-specific rules to arithmetic and assignments.

| Operation | Result |
|---|---|
| INR + INR | Valid — INR |
| INR - INR | Valid — INR |
| INR + USD | Error |
| INR × scalar | Valid — INR |
| INR × USD | Error |
| INR ÷ INR | Valid — numeric ratio |
| INR ÷ scalar | Valid — INR |
| Assigning a plain number to a currency variable | Error |

The same compatibility principles apply to USD, EUR, and GBP.

## Requirements

- Python 3.10 or later
- A C compiler such as GCC, if you want to compile and execute the generated C source

The Python implementation uses standard-library modules and does not require third-party parser generators.

## Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/YOUR_USERNAME/currency-c-compiler.git
cd currency-c-compiler
```

### 2. Run the compiler

Using the included sample program:

```bash
python codegen.py sample.cur
```

The compiler processes the source and generates:

```text
output.c
```

You can also provide another Currency-C source file:

```bash
python codegen.py program.cur
```

### 3. Generate plain output

To disable variable labels and input prompts in generated C:

```bash
python codegen.py sample.cur --plain
```

### 4. Inspect the AST

```bash
python codegen.py sample.cur --dump-ast
```

This displays the parsed AST and exits without generating C.

### 5. Compile the generated C code

If GCC is installed:

```bash
gcc output.c -o program
```

Execute it:

```bash
./program
```

On Windows:

```powershell
.\program.exe
```

## Error Handling

The compiler reports errors at different stages:

- **Lexical errors:** Unexpected characters and unterminated block comments.
- **Syntax errors:** Invalid token sequences or violations of the implemented grammar.
- **Semantic errors:** Undeclared identifiers, incompatible assignments, invalid currency arithmetic, and other type violations.

Code generation is skipped when semantic errors are detected.

## Design and Implementation

The project uses several fundamental compiler construction concepts:

- Regular-expression-based lexical analysis.
- Recursive descent parsing.
- Abstract Syntax Tree construction.
- Symbol tables and scoped name resolution.
- Static semantic analysis and type checking.
- Visitor-based AST traversal.
- Source-to-source code generation.

## Current Scope and Limitations

Currency-C is a restricted C-like language, not a complete implementation of the C programming language.

- Function definitions and user-defined function calls are not part of the implemented grammar.
- Currency values are represented as floating-point values in generated C; currency codes are enforced during semantic analysis rather than preserved as distinct runtime types.
- Automatic exchange-rate conversion is not implemented.
- The language supports only the constructs defined by its current grammar and semantic rules.
- Generated C code must be compiled separately using a C compiler.
